## Workflow

`CLI` below means `node ${CLAUDE_SKILL_DIR}/scripts/medtech-data.mjs`.

1. **Pick the dataset.** Use the aliases below. For anything else, run `CLI datasets --search <words>`; the catalog has about 100 dataset families.
2. **Get exact column names.** Run `CLI columns <dataset>`, or see [references/datasets.md](references/datasets.md). Names are case-sensitive in filters and differ between datasets.
3. **Count first.** Run `CLI query <dataset> --where ... --count`.
4. **Pull rows.** Use `--columns` to trim output and `--sort -Col --limit N` for top-N.

```bash
# National volume for a code family (not subject to the small-provider redaction)
CLI query geography --where Rndrng_Prvdr_Geo_Lvl=National --in HCPCS_Cd=27447,27130 --format csv
# Top surgeons for a code in a state, a given year
CLI query provider --year 2023 --where HCPCS_Cd=27447 --where Rndrng_Prvdr_State_Abrvtn=TX \
  --columns Rndrng_NPI,Rndrng_Prvdr_Last_Org_Name,Rndrng_Prvdr_First_Name,Rndrng_Prvdr_Type,Tot_Benes,Tot_Srvcs \
  --sort -Tot_Srvcs --limit 25 --format csv
# Hospital outpatient department volume for a code
CLI query outGeo --where Rndrng_Prvdr_Geo_Lvl=National --where HCPCS_Cd=27447
# MS-DRG discharges, national, and top hospitals
CLI query inpGeo --where Rndrng_Prvdr_Geo_Lvl=National --where DRG_Cd=470
CLI query inpProvider --where DRG_Cd=470 --where Rndrng_Prvdr_State_Abrvtn=OH --sort -Tot_Dschrgs --limit 20
# Original Medicare vs Medicare Advantage share (latest full year)
CLI ffs-share --state TX
CLI ffs-share --state VT --by-county --format csv
CLI ffs-share --state TX --year 2024        # match the claims year; the default is the latest full year
```

## Dataset aliases

| Alias | Dataset | One row per |
|---|---|---|
| `provider` | Physician & Other Practitioners by Provider and Service | NPI × HCPCS × place of service |
| `provSummary` | Physician & Other Practitioners by Provider | NPI (true distinct `Tot_Benes`) |
| `geography` | Physician & Other Practitioners by Geography and Service | National/State × HCPCS × place of service |
| `inpProvider` | Inpatient Hospitals by Provider and Service | hospital CCN × MS-DRG |
| `inpGeo` | Inpatient Hospitals by Geography and Service | National/State × MS-DRG |
| `outProvider` | Outpatient Hospitals by Provider and Service | hospital CCN × APC (no HCPCS) |
| `outGeo` | Outpatient Hospitals by Geography and Service | National/State × APC, plus HCPCS rows for some codes |
| `dmeGeo` | DMEPOS by Geography and Service | geo level × HCPCS |
| `dmeReferring` | DMEPOS by Referring Provider and Service | ordering NPI × HCPCS |
| `enrollment` | Medicare Monthly Enrollment | month (or annual) × nation/state/county |

- **One dataset per year:** each claims year is its own dataset with its own ID. `--year` picks one; the default is the newest.
- **Lag:** claims data runs about two years behind.
- **Enrollment is the exception:** it's one rolling dataset. Filter `--where YEAR=2024` instead of using `--year`, or use `ffs-share`.

## API rules (enforced by the CLI; follow them if you build URLs by hand)

These were verified live on 2026-10-26.

**Filters and column names**
- **An unknown column in a filter, sort or column list is silently ignored.** You get unfiltered rows with HTTP 200. The CLI checks every name against the dataset's real column list first.
- **Column names are case-sensitive** (`HCPCS_Cd`, but DMEPOS Referring uses `HCPCS_CD`). **Values are not** (contains "ortho" matches "Orthopedic Surgery").
- **Combine 2+ conditions in an explicit AND group.** CMS has combined a bare list of conditions with OR before.
- `keyword=` is a full-text search across all columns, not a code filter.

**Paging and numbers**
- Pages of up to 5,000 rows are reliable; oversized pages are silently truncated.
- Numbers come back as strings.
- With curl, pass `-g` so the `[ ]` in filter parameters isn't treated as a glob.

**Catalog**
- In `data.json`, the date in a dataset's title is the release date, not the data year. The data year is in `temporal[0].startDate`.
- The newest year has two IDs: a moving "latest" alias and a pinned one. Prefer the pinned ID.

## Reading the numbers correctly

Flag whichever of these affect your answer.

**Coverage**
- **Medicare fee-for-service only.** No Medicare Advantage, Medicaid or commercial claims. Use `ffs-share` to say how much of the Medicare population a figure covers, and keep it separate from any estimate.
- **Small providers are redacted.** By-Provider rows are suppressed at ≤10 beneficiaries, so summing them undercounts. Use the `geography`, `inpGeo` and `outGeo` totals for true totals.

**Counting procedures**
- **For surgical codes, services are not procedures. Lead with beneficiaries.** Assistant-at-surgery lines (PAs, NPs) and ambulatory surgery center (ASC) facility claims bill the same CPT code, so `Tot_Srvcs` can run near 2× the real number of operations.
  - For "how many procedures/surgeries were done", the headline number is `Tot_Benes` (national or state geography rows), stated as "≈ N procedures (Medicare FFS beneficiaries)". Mention services second, if at all, labelled "billed lines".
  - Sum `Tot_Benes` across the place-of-service rows (`F` + `O`) for the headline, and note that a patient in both rows could be counted twice. Office rows are usually tiny for surgical codes. Say which rows you summed, so answers are comparable.
  - For ranking surgeons, rank individuals (`Rndrng_Prvdr_Ent_Cd=I`) in surgical specialties by `Tot_Benes`. Exclude ASCs (`Ent_Cd=O`), physician assistants and nurse practitioners, and say you did.
- **Beneficiary counts are distinct per row.** Summing `Tot_Benes` across codes or places of service overcounts patients. Use `provSummary` for one provider's true count.
- **Place of service:** `F` = facility, `O` = office. A code usually has both rows.
- **`HCPCS_Desc` is CMS's plain-language label, not the CPT descriptor.** For example, 27447 reads "Replacement of knee joint, both sides of knee"; that's normal total knee arthroplasty, not bilateral surgery.

**Payments**
- Per-row average payments mix surgeon and assistant claims, so one row's average is not the fee-schedule rate.
- Total paid ≈ average Medicare payment × services (or × discharges for inpatient).

**Outpatient file (`outGeo`)**
- `Srvc_Lvl` is `APC` (a whole payment group) or `APC-HCPCS` (one code within it).
- Only some codes get HCPCS rows. **An absent code is not zero.** Codes on Medicare's inpatient-only list don't appear, for example.
- `Bene_Cnt` = beneficiaries; `CAPC_Srvcs` = comprehensive-APC services.

**Comparing settings**
- Physician-file totals cover every setting.
- Hospital outpatient department (`outGeo`), inpatient (`inpGeo`, by DRG) and ASC volumes are partial views of that whole. See `medtech-market-intel` for combining them.

**Enrollment (`ffs-share`)**
- `MA_AND_OTH_BENES` includes Medicare Advantage plus other non-fee-for-service plans (cost plans, PACE).
- The annual (`MONTH=Year`) row's exact definition is in CMS's data dictionary; I haven't verified whether it's an average or a count. Say "annual enrollment row" rather than guessing.
- The current year has monthly rows only.
- `ffs-share` with no `--state` gives the national figure (`--state US` works too). `MONTH` is text, so sorting on it is alphabetical, not calendar order.

**Other identifiers**
- **Geography:** physician, inpatient and outpatient files use `Rndrng_Prvdr_Geo_Lvl` (National/State), with full state names in `_Geo_Desc`. DMEPOS uses `Rfrg_Prvdr_Geo_Lvl`.
- **Entity type:** `Rndrng_Prvdr_Ent_Cd` is `I` (individual) or `O` (organization).
- **Level II HCPCS codes** billed by DME suppliers are only in `dmeGeo` and `dmeReferring`. `C` codes have no per-code public data.
